# 01.3 Database and migrations

Feature: 01 Backend foundation
Depends on: 01.1, 01.2

Goal: a SQLite database the backend opens at startup, with numbered migration files that create and evolve its tables, so later specs (02.1, 03.1, 09.1, 12.1, …) only have to add a migration.

Behavior
- New setting `STORYMAKER_DATA_DIR` (default `backend/data/`), added to `Settings` and `.env.example`. The database file is `<data dir>/storymaker.db`. The folder is created if missing.
- Uses Python's built-in `sqlite3` with plain SQL (no ORM, no new dependency).
- Every connection: foreign keys enforced, write-ahead logging (readers aren't blocked while a background job writes), rows readable by column name.
- One connection per request, given to endpoints by a FastAPI dependency `get_db()`, closed afterwards.
- Migrations are SQL files in `storymaker/migrations/`, named `NNNN_<what>.sql` (e.g. `0001_trips_and_members.sql`).
- At startup, unapplied migrations run in number order, each in its own transaction, and are recorded in a `schema_migrations` table. Restarting never runs one twice.
- A failing migration is rolled back completely, and startup stops with an error naming the file.
- This spec ships the mechanism with **no** table migrations. 02.1 adds the first one.
- Tests: every test gets its own empty database in a temporary folder; the real `backend/data/` is never touched.
- `backend/data/` is ignored by git.

Acceptance
- [x] With no data folder, starting the app creates `backend/data/storymaker.db`, and `/health` still works.
- [x] Two test migrations run in number order and are recorded; a second startup runs nothing.
- [x] A broken migration leaves no partial changes and stops startup with an error that names the file.
- [x] Foreign keys are enforced (a test inserts a row pointing to a missing parent and gets an error).
- [x] Tests run on a fresh temporary database each, and `backend/data/` is untouched after `uv run pytest`.
- [x] `backend/data/` is ignored by git; `STORYMAKER_DATA_DIR` is in `Settings` and `.env.example`.

Out of scope: any real tables (02.1 onwards), undoing migrations, backups, the story-job checkpoint store (12.3).
Later: none
