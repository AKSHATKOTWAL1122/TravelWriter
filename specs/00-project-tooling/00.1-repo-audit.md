# 00.1 Repo audit before every push

Feature: 00 Project tooling
Depends on: none

Goal: an automatic check that the specs, issues log, settings and code agree with each other and that nothing secret is committed, run before every push to the public GitHub repo, so inconsistencies are caught by a script and not left to memory.

Behavior
- `scripts/audit.py` checks one git revision (default `HEAD`; `--rev` to choose another), e.g. `python3 scripts/audit.py --rev main`. Standard library only, so it runs without the backend's environment.
- **Roadmap ↔ spec files:** every linked spec file exists; every spec file is linked; a spec with status `written`/`approved`/`done`/`changing` has a file; a `done` spec has every acceptance box ticked; each file's title starts with its ID; every ID in "Depends on" exists in the roadmap.
- **Stale text:** a `done` spec contains no "pending your answer" or "Proposed:" markers. The **Changes section is skipped**, since it may describe what was fixed, and so are quoted mentions (in "…" or `…`), so a spec can name the markers (ISSUE-050).
- **Issues log:** IDs are unique with no gaps; resolved issues are in ID order; every spec number in a resolution exists in the roadmap. Open issues are *listed*, not failures, because decisions can be pending.
- **Settings:** every setting in `Settings` appears in `backend/.env.example`, and secret-looking settings there (`*_KEY`, `*_SECRET`, `*_TOKEN`) have empty values.
- **CLAUDE.md:** every `backend/…` file path it mentions exists.
- **Hygiene and secrets:** no tracked `.env`, database, `__pycache__` or `.DS_Store` files; no Google-style API keys (`AIza…`) or filled-in `…_KEY=`/`…_SECRET=`/`…_TOKEN=` lines in any tracked file.
- Prints each finding with its file, and exits with a non-zero code if there are any, so it can block a push.
- CLAUDE.md rule 9 changes: before every push, run the audit **and** the tests, and push only if both pass. The audit replaces the hand-written secret scan.
- If the format of the roadmap, issues log or spec files ever changes, `audit.py` is updated in the same change.

Acceptance
- [x] `python3 scripts/audit.py --rev main` passes on the current repo (no findings, exit code 0).
- [x] Each check has a test that builds a small throwaway git repo with exactly that problem and confirms it's reported with a non-zero exit code.
- [x] The "Proposed:" quoted inside a Changes section is **not** reported (the false alarm from the last audit).
- [x] Open issues are listed but don't fail the audit.
- [x] CLAUDE.md rule 9 and the Commands table are updated.

Out of scope: judging whether specs *make sense together* (that stays the human + Claude consistency check, rule 4), mobile-app checks (added when `mobile/` exists), running on GitHub's servers.
Later: run the same audit automatically on GitHub for every push (GitHub Actions), once we want that.

Consistency check (vs. all specs + CLAUDE.md)
- Checked against: CLAUDE.md (rules 2, 4, 5, 8, 9; Commands; Layout), `specs/_template.md`, `specs/README.md` row format, `specs/ISSUES.md` table format, 01.2 (`Settings`, `.env.example`), 01.1 (`.gitignore`), product decisions (public repo).
- Findings: ISSUE-050 (found while building): once 00.1 is `done`, its own text quotes the stale-text markers, so the check would flag 00.1 itself. Quoted mentions are now skipped. Also, the audit depends on the current formats of the roadmap rows, issue rows and spec headers, so the coupling is written into the behavior: format changes update `audit.py` in the same change.
- No clash:
  - It complements rule 4: it catches mechanical mismatches, while judgement stays with the per-spec check.
  - The secret checks cover today's key and the future signing secret (03.8) by name pattern.
  - Running from the repo root with plain `python3` needs no new dependency.
