# 02.5 Join-trip endpoint

Feature: 02 Trips
Depends on: 02.1, 02.2, 02.3, 02.4

Goal: a friend joins a trip with its code and their name, and gets their own token, just like the creator did.

Behavior
- `POST /api/trips/join` with `{"join_code": "…", "display_name": "…"}`, no token needed. Answers `201` in the same shape as 02.3, with `role` `member`.
- The code is read with `normalize_join_code` (02.2), so "k7m pq4" works. An unknown code, or one that can't be a code → `404 trip_not_found` ("No trip has that code").
- The name follows 02.3's `MemberName` rules and is stored as typed. A name already in the trip, ignoring case and spaces (02.1's `name_key`) → `409 name_taken`, with a message pointing a returning member to "I'm already in this trip" (02.7, 05.4). The same name in another trip is fine.
  - If two people take the same name at the same moment, the second still gets `409 name_taken`, not an error.
- Joining an **ended** trip is allowed: the new member can read the stories and add moments taken during the trip (09.3). Their moments reach the full-trip story only if it hasn't been written yet.
- No limit on group size (CLAUDE.md).

Acceptance
- [x] Joining a trip from `POST /api/trips` with a new name returns `201` in 02.3's shape with `role` `member`; the member is saved in that trip with the token's hash, and the token works with 02.4.
- [x] The code typed loosely (lowercase, with a space or dash) works.
- [x] An unknown code, "K0MPQ4" and "" → `404 trip_not_found`.
- [x] "asha " when "Asha" is already in the trip → `409 name_taken` and no member is added; "Asha" in another trip is fine.
- [x] When the name is taken between the check and the save, the answer is still `409 name_taken`.
- [x] 02.3's name rules apply: "Asha 2" → `422 validation_error`.
- [x] Joining an ended trip works.

Out of scope: rejoining as an existing member (02.7–02.9), limiting wrong-code attempts (ISSUE-051), the app's join screen (05.2).
Later: none
