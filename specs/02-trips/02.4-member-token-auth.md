# 02.4 Member token auth

Feature: 02 Trips
Depends on: 01.4, 02.1, 02.3

Goal: endpoints that need to know who's calling get the current member from the token the phone sends, and trip endpoints turn away members of other trips.

Behavior
- The phone sends its token (from 02.3 or 02.5, or from a rejoin request, 02.7, once approved, 02.8) as `Authorization: Bearer <token>`.
- `current_member` (a FastAPI dependency in `storymaker/auth.py`) hashes the token with `hash_token()` (02.3) and finds the member with that `token_hash` (02.1). The endpoint gets the member's `id`, `trip_id`, `display_name` and `role`.
  - No header, or not in the form `Bearer <token>` → `401 token_missing`.
  - No member has that token (made up, or replaced by a rejoin, 02.8) → `401 token_invalid`.
- `trip_member` does the same for paths with a `{trip_id}`, and answers `403 not_a_member` if the member belongs to another trip. A trip ID that doesn't exist gets the same answer, so outsiders can't probe for trips.
- Tokens don't expire. One works until a rejoin replaces it (02.8, ISSUE-047), also after the trip ends, so people can still read the stories.
- **Guarded saves** (ISSUE-064): `CurrentMember` also carries the login's `token_hash` (never sent back). A save that depends on who's calling adds the shared condition `STILL_SIGNED_IN` to its `WHERE`, so it only counts if the caller's login still works at that moment; a rejoin approved in the same instant (02.8) moves it to a new phone. If it doesn't count → `401 token_invalid`, and nothing changes.
- No token needed for: creating a trip (02.3), joining (02.5), a rejoin request (02.7), and `/health`. Checking a rejoin request (02.9) uses the token that came with it, which isn't a member's yet.

Acceptance
- [x] A test-only route with `current_member` gets the right member for a token from `POST /api/trips`.
- [x] No header, a `Basic …` header, or `Bearer` with nothing after it → `401 token_missing`; a made-up token → `401 token_invalid`; both in 01.4's error shape.
- [x] After a member's `token_hash` is replaced (as 02.8 will do), the old token gets `401 token_invalid` and the new one works.
- [x] A test-only route under `/api/trips/{trip_id}/…` with `trip_member` answers that trip's member, and gives `403 not_a_member` to a member of another trip and for a made-up trip ID.
- [x] A token still works after its trip is set to `ended`.
- [x] `CurrentMember` carries the member's `token_hash`; `STILL_SIGNED_IN` holds for it until that hash is replaced (as 02.8 does), then no longer (ISSUE-064, rule 5).

Out of scope: creator-only checks (first needed in 02.8), what the app shows after a `401` (04.2, 04.4), signed media links (03.8, which don't use the token).
Later: none

Consistency check (vs. all specs + CLAUDE.md)
- Checked against: CLAUDE.md (Rules: endpoints follow 01.4), product decisions (lost phone ISSUE-047/048, ending the trip ISSUE-001/033), 01.4, 02.1, 02.3, 02.5–02.9, 03.x, 03.8, 04.2–04.4, 09.2–09.7, 12.2, 12.4, 13.x.
- Findings: none. Tokens not expiring follows from the lost-phone decision (a login lasts until a rejoin replaces it); recorded as a product decision for approval.
- No clash:
  - Uses 02.1's unique `token_hash` and 02.3's `hash_token()`; the token itself is never stored or logged.
  - `not_a_member` is the code 01.4 already names as an example; `trip_id` matches 01.4's example path.
  - One token per member, one member per trip: matches 02.1 (one `token_hash` column) and 09.4 (each phone reports its own outbox).
  - 02.6, 03.x, 09.x and 12.x trip endpoints use `trip_member`; 02.8, 02.10 and 02.11 add their checks on who may decide a rejoin request on top.
  - The lost phone has no token, so 02.7 works without one; 02.9 uses the not-yet-working token 02.7 returned (ISSUE-055).
  - Signed media links (03.8) carry their own signature, because image loaders can't send headers.
  - No new setting or dependency.
