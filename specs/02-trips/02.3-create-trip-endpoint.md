# 02.3 Create-trip endpoint

Feature: 02 Trips
Depends on: 01.4, 02.1, 02.2

Goal: anyone can start a trip by naming it and themselves; they become its creator and get the join code to invite friends plus a token that logs this phone in.

Behavior
- `POST /api/trips` with `{"trip_name": "…", "display_name": "…"}`, no token needed. Answers `201` with `{"trip": {"id", "name", "join_code", "status", "created_at"}, "member": {"id", "display_name", "role", "joined_at"}, "token": "…"}`.
- The trip (`active`, code from `new_join_code`, 02.2) and its `creator` are saved in one transaction: both or neither.
- **Names** are checked by the types `TripName` and `MemberName` (`storymaker/names.py`, reused by 02.5 and 02.7) and stored exactly as typed, not trimmed:
  - Allowed: letters in any language with their accent and vowel marks, spaces, `-` `'` `.` (also as `’` or full-width), the name dots `·` `・`, and the invisible joiners Persian and Indian scripts need. No emoji, symbols or other punctuation. At least one letter.
  - Member name: no digits; 1–10 words and at most 60 characters.
  - Trip name: digits in any script allowed; 1–50 words and at most 300 characters.
  - Words are separated by spaces, so the character cap is what limits languages written without them (ISSUE-052).
  - A bad name → `422 validation_error` (01.4), with a message naming the field and the rule.
- **Token:** `new_token()` (`storymaker/tokens.py`) makes a random URL-safe token (256 bits, `secrets`) and its SHA-256 hash. Only the hash is stored (02.1); the token appears once, in this response. 02.4 checks tokens with `hash_token()`.

Acceptance
- [x] Creating "Goa 2026" as "Jean-Luc" returns `201` in the shape above; the database has one `active` trip and its `creator`, whose `token_hash` is the SHA-256 of the returned token. The token itself isn't stored.
- [x] Names come back exactly as typed: " Asha " stays " Asha ".
- [x] Accepted member names: "Zoë", "O’Brien", "J. R. Silva", "प्रिया", "محمد", "علی‌رضا", "ジョン・スミス", "张伟"; trip names: "北海道の冬旅行2026", "Mia's 30th".
- [x] Refused with `422 validation_error` naming the field: member names "Asha!!", "DJ_K", "Asha 2", "🙂", "@asha", "   ", "", 11 words, 61 characters; trip names "Lisbon & Porto", "Road trip 🚗", 51 words, 301 characters.
- [x] Two trips get different IDs, join codes and tokens.
- [x] If saving the creator fails, no trip is left behind.

Out of scope: checking tokens (02.4), joining (02.5), reading a trip (02.6), the app's create screen (05.1).
Later: none

Consistency check (vs. all specs + CLAUDE.md)
- Checked against: CLAUDE.md (destination-agnostic, any language; Rules: endpoints follow 01.4, settings), product decisions (names unique per trip, lost phone, join code), 00.1, 01.3, 01.4, 02.1, 02.2, 02.4–02.9, 04.2, 04.3, 05.1–05.5, 06.3, 11.x (stories use member names), 12.4.
- Findings:
  - ISSUE-052 (decision, resolved): word limits alone don't limit names in languages without spaces, and "not trimmed" + "non-empty" left a name of only spaces open. You chose character caps too, and at least one letter.
  - ISSUE-053 (change to 01.4, approved): nothing loaded endpoint modules, so every endpoint spec would have had to edit `main.py`. Now every module in `storymaker/endpoints/` is loaded at startup; 02.3's `trips.py` is the first.
- No clash:
  - Fills 02.1's columns: `trips.name`, `members.display_name`, `name_key` (from `name_key()`), `role`, `token_hash`, `joined_at`.
  - Uses 01.4's `new_id()`, `utc_now_iso()` and error shape, and 02.2's `new_join_code`.
  - Names are stored as typed, but uniqueness still ignores case and spaces (02.1), so " Asha " and "Asha" are the same person when joining (02.5).
  - 02.4 checks tokens with `hash_token()`, and 02.7 gives a rejoining phone its new token with `new_token()` (ISSUE-055); 04.3 keeps the token and trip from this response; 02.6 reuses the `trip` object's shape.
  - 05.1 and 05.2 must apply the same name rules on the phone and count characters like the server (code points: `[...name].length`, not `.length`). Roadmap lines updated.
  - No new setting or dependency (`unicodedata`, `secrets`, `hashlib` are built in); no fields for places or routes.
