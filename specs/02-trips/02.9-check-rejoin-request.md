# 02.9 Check a rejoin request

Feature: 02 Trips
Depends on: 01.4, 02.4, 02.7, 02.8

Goal: the new phone that asked to rejoin (02.7) finds out whether its request was approved, declined or replaced, using the token that came with it.

Behavior
- `GET /api/trips/{trip_id}/rejoin-requests/{request_id}` with `Authorization: Bearer <token>`, the token 02.7 returned with that request. Answers `200` with `{"request": {"id", "status", "created_at"}}`: 02.7's object, with `status` `pending`, `approved`, `declined` or `replaced`.
- Only that request's own token opens it, whatever its status, also in an ended trip. The token is matched against the request's stored hash, not against members, so it works while the request is pending; 02.4 still turns it away everywhere else.
- `approved`: the same token is now the member's login (02.8), so the phone loads the trip (02.6) with it. `declined` or `replaced`: the token will never work; the person can ask again (02.7).
- Checking changes nothing in the database.
- Errors: no header, or not `Bearer <token>` → `401 token_missing` (as 02.4). No such request in this trip, or the token isn't this request's (another request's, a member's or made up) → `404 request_not_found` (02.8), so nobody can probe for requests or trips.

Acceptance
- [x] Tomás asks to rejoin: checking with the request's token → `200`, `pending`, in the shape above; the same token still gets `401 token_invalid` from 02.6.
- [x] The creator approves: checking → `approved`, and the same token now loads the trip (02.6) as Tomás.
- [x] Declined → `declined`. Asking again → the first request checks as `replaced` and the second as `pending`, each only with its own token.
- [x] No header → `401 token_missing`. Tomás's old token, the creator's token, the other request's token, a made-up token, a made-up request ID, or the right request under another trip's ID → `404 request_not_found`.
- [x] Works the same in an ended trip; the database is unchanged after checking.

Out of scope: when the creator's own request takes effect (02.10, 02.11), the waiting screen and how often it checks (05.4), the requester cancelling their request.
Later: the requester cancels their own pending request (e.g. the old phone turned up); the answer says who can decide it, so 05.4 can say "ask Hana".
