# 02.6 Get-trip endpoint

Feature: 02 Trips
Depends on: 02.1, 02.3, 02.4

Goal: a member's phone can load its trip at any time: the name, join code, status and who's in it.

Behavior
- `GET /api/trips/{trip_id}`, for members of that trip only (`trip_member`, 02.4). Answers `200` with `{"trip": {…}, "members": [{…}, …]}`.
  - `trip` is the same object as in 02.3: `id`, `name`, `join_code`, `status`, `created_at`. Every member sees the code, so anyone can invite (05.3).
  - `members` lists each member's `id`, `display_name`, `role` and `joined_at`, in the order they joined, creator first. Names are exactly as typed.
- Never includes tokens or token hashes.
- An ended trip loads the same way, with `status` `ended`.
- Errors come from 02.4: `401 token_missing` or `token_invalid`, and `403 not_a_member` (also for a trip ID that doesn't exist).

Acceptance
- [x] After a creator and two friends join, each of them gets `200` with the trip (02.3's fields) and three members in join order, creator first.
- [x] Nothing in the response is a token or a `token_hash`.
- [x] A member of another trip, or a made-up trip ID → `403 not_a_member`; no token → `401 token_missing`.
- [x] An ended trip comes back with `status` `ended`.

Out of scope: parts and stories (12.4), rejoin requests (02.8), member colors (06.3, made in the app), changing the trip name.
