# 02.2 Join-code generator

Feature: 02 Trips
Depends on: 02.1

Goal: every trip gets a short code friends can type or receive from the share sheet, plus one function that reads a typed code however it was typed.

Behavior
- A code is **6 characters** from 31 symbols: A–Z and 2–9, without the look-alikes O, I and L. About 887 million codes, e.g. `K7MPQ4`.
- `new_join_code(conn)` returns a random code (Python's `secrets`, so codes can't be predicted) that no trip uses yet, ended trips included, so codes are never reused. It picks again on a clash and raises an error after 10 tries. The `UNIQUE` constraint on `trips.join_code` (02.1) stays the final guard.
- `normalize_join_code(typed)` returns the stored form of what a person typed, or raises `ValueError` if it can't be a code:
  - case, spaces and dashes of any kind (`-`, `–`) are ignored, and full-width characters from some Asian keyboards count as normal ones (`Ｋ７Ｍ` = `K7M`);
  - wrong length, or any character outside the 31 symbols, is rejected.
- The database and the API use the 6 plain characters. The app may show them grouped, e.g. `K7M PQ4` (05.1, 05.3).
- A join code is not an ID: trips still get their `id` from `new_id()` (01.4).

Acceptance
- [x] 10,000 new codes are all 6 characters from the 31 symbols.
- [x] `new_join_code` skips a code another trip already has, even an ended one (the test makes the first random pick a taken code).
- [x] If every pick is taken, it raises an error after 10 tries instead of looping forever.
- [x] "k7m pq4", "K7M-PQ4", " k7m–pq4 " and "Ｋ７ＭＰＱ４" all normalize to `K7MPQ4`.
- [x] "K7MPQ", "K7MPQ44", "K0MPQ4", "K7M?Q4" and "" raise `ValueError`.

Out of scope: the create-trip (02.3), join (02.5) and rejoin (02.7) endpoints and their error codes; changing a trip's code.
Later: the creator can reset a leaked code.

Consistency check (vs. all specs + CLAUDE.md)
- Checked against: CLAUDE.md (destination-agnostic; Rules: endpoints follow 01.4), product decisions (members, lost phone, hosting ISSUE-015), 00.1, 01.3, 01.4, 02.1, 02.3–02.9, 04.2, 05.1–05.5.
- Findings: ISSUE-051 (gap): no spec limits wrong-code attempts, so someone could try codes until one works. Harmless while the backend only runs on local Wi-Fi (ISSUE-015), but it should be settled before real hosting.
- No clash:
  - 02.1's `join_code TEXT NOT NULL UNIQUE` holds the plain form, so "k7m pq4" and "K7MPQ4" can never become two trips' codes.
  - The name `normalize_join_code` and the `ValueError` follow 01.4's `normalize_iso`.
  - 02.3 calls `new_join_code`; 02.5 and 02.7 call `normalize_join_code` on the typed code. How a malformed or unknown code is answered (and whether an ended trip's code still lets *new* people join) is decided in 02.5.
  - 05.2 can send the code as typed: only the server reads it, so the phone and server can't disagree.
  - No words in codes, so there's no language bias (CLAUDE.md), and full-width input from Asian keyboards works.
  - No new setting or dependency (`secrets` and `unicodedata` are built in); nothing new for the 00.1 audit.
